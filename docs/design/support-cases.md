# Employee support cases

Mode: Operate. Extend the incumbent `/service` workspace using `DESIGN.md` and `src/service/style.css`. No new visual world or external asset is introduced.

Raise a question from a statement, identify the responsible colleague, read replies and confirm the current resolution. Case status stays separate from financial status. Use native labeled forms, a narrow case list beside the conversation and a single column on phones. Thread rows use hairlines and generous spacing. Privacy, uncertain-save retry and missing-assignee recovery explain the relevant actions.

Verification covers desktop/390-pixel flows, linked statements, loading/empty/error, access loss, history pagination, keyboard focus, escaped multiline replies, closure and uncertain retries. Finish evidence will be recorded after these checks.

## Finish review

The browser exercise used two real synthetic local accounts: driver statement→linked case, assigned administrator explanation, reporter confirmation on a 390-pixel phone viewport, and return to the same €1.33 draft/digest. Desktop columns measured 314/708 pixels; the phone conversation was 290 pixels wide inside its existing account surface, with no horizontal overflow and 44-pixel action controls. Source UI tests cover escaped replies, uncertain exact retry, access loss, closure, generic context clearing and unseen concurrent resolution during history paging. The adversarial review found and verified fixes for those last two context/concurrency issues. No raster asset ships.
